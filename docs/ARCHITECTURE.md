# Architecture

WEBFORGE separates four authorities:

1. **Domain intelligence** — intent, capabilities, patterns, runtime, components, tools.
2. **Deterministic policy** — trust/license/runtime/release hard gates.
3. **Execution adapters** — conditional integration surfaces; never implicit trust.
4. **Evidence** — every verification records a machine-readable receipt.

## Knowledge graph

`COMPONENT → best_for → USE CASE`

`COMPONENT → requires → CAPABILITY`

`COMPONENT → compatible_with → RUNTIME`

`COMPONENT → implemented_by → TOOL`

`COMPONENT → governed_by → POLICY`

`COMPONENT → evidence → REAL RESULTS`

## Adaptive composition

Homepage composition is brief-derived rather than template-selected:

`BRIEF → DOMAIN / GENOME → PRODUCT → DESIGN STRATEGY → COMPOSITION PROFILE → SECTION PLAN → METADATA-SCORED COMPONENTS → SPATIAL COMPOSITION → DETERMINISTIC RENDERER`

The composition profile carries the site archetype, homepage section intent, conversion flow and visual character. Known domains use semantic profiles; `NOVEL` domains retain project-local synthesis and production-review fail-closed behavior.

Section implementations are still resolved through the governed component registry. A profile chooses semantic needs, not raw HTML/CSS templates, so reusable renderer packages remain composable and independently governed.
